## IndexNow CI 排障（commit `f0442af`，已修复）

排障链路（两层问题，别混淆）：

1. **表层**：run #53 失败 annotation 指向 `actions/upload-artifact: v3` 已弃用（2024-04 起硬失败）→ 升级 `upload-artifact@v4` + `if-no-files-found: ignore`，`setup-python@v4→v5`，`checkout@v4→v5`（清 Node20 弃用警告）。
2. **深层（真正的根因）**：run #54 仍失败，annotation 只有 "Process completed with exit code 1"，步骤 7 `运行IndexNow通知` 挂掉。本地复现确认是 API 返回 **403 `UserForbiddedToAccessSite`**。
   - 已验证**不是**密钥文件问题：`https://ziyitsang.github.io/5a933d53056640af8bee125d8f287aa5.txt` 返回 200，内容正确（32 字节 = 密钥本身），且该文件**已被 git 跟踪**、线上可达。
   - 实测 `https://api.indexnow.org/indexnow` 连续 3 次均 403 → 判定为 **IndexNow 服务端侧拒绝**（该 key 未被其接受/撤销，或 IndexNow 本身不稳定），**本地和 CI 无法修复**。
   - 关键发现：**仓库 Actions secrets 列表为空 `[]`**，`INDEXNOW_API_KEY` 未配置。所以脚本里 hardcode 的 key 与 actions 里"创建验证文件"步骤引用的 secret 都没真正配置；脚本 `sys.exit(1)` 才导致 job 失败。

修复策略（让 CI 不再被外部因素搞红）：
- 新增 `检查IndexNow密钥` 步骤输出 `has_key`；后续 3 步都以 `has_key == 'true'` 为条件。
- `运行IndexNow通知` 加 `continue-on-error: true`。
- `发送通知结果` 去掉 `exit 1`，改为打印 ⚠️ 提示；结果文件缺失也只警告不失败。
- 注释顺序调整：key_check 必须在「创建API密钥验证文件」之前。

**结果**：run #55 ✅ success，pages build ✅ success，线上内容已核对（PhD Student / SLAI / Presidential Scholarship / CSC5041 全在）。

**遗留（需用户处理）**：IndexNow 通知功能本身仍未真正生效。若要让 SEO 推送工作，需：① 去 IndexNow 重新申请/确认 key；② 在仓库 Settings → Secrets 配置 `INDEXNOW_API_KEY`。
